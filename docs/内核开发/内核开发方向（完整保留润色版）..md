# 内核开发方向

## 前言

首先，欢迎大家加入内核开发交流群。大家可能对内核开发感兴趣，也可能只是想尝试一下。不管出于什么原因，能聚在一起就是缘分。下面，我会给大家介绍这个方向的大致情况，以及需要涉及的知识。

## 方向前提（一）：先把困难讲清楚

在介绍知识范围之前，可能要先给大家泼一盆冷水。有些事情，需要在选择这个方向之前想清楚。

**内核开发很难，而且是一个反馈往往很慢的方向。** 就我目前在曲师大的了解，与内核开发直接相关、能够获得认可的比赛也寥寥无几。选择这条路，可能意味着很少有人与你同路：你想分享的知识，别人未必感兴趣；你拿出来的项目，别人也未必看得懂。它没有直观好看的 UI，也没有大家熟悉的后端框架，很多成果甚至需要先解释一大堆背景，才能让人明白你做了什么。

当然，现在有了这个群，至少我们有了一个能够讨论问题、分享进展的地方。

内核开发的一道难关，就是漫长的入门阶段。根据个人基础和投入时间的不同，你可能要经过**几个月**的学习，才会**开始**真正进入内核开发。前期需要学习 C 语言、操作系统、计算机组成原理，阅读已有的 OS 项目，同时查阅特权架构手册和各种设备、驱动相关文档。

而且，**特权架构手册是参考手册，不是操作系统实现教程。** 它会告诉你硬件提供了什么、指令和寄存器如何工作，但不会一步步教你怎样写出一个操作系统。你还需要自己理解：操作系统为什么要这样设计？这些机制应该怎样组织起来？代码为什么能运行，又为什么会出错？

这些困难不会因为建了一个群就消失。群里可以交流问题，把方向和任务拆得更细，让大家少走一些弯路，但阅读、思考、调试和动手实现，最终都要自己完成。

我希望大家在了解这些之后，再决定是否投入。**如果知道它难、知道它需要长期投入，仍然愿意继续，那就一起往下走。**

## 方向前提（二）：主动探索，认真提问

选择这条路，就意味着很多问题需要你亲手解决，不能一直依赖别人。

群里可以讨论，但请尊重自己的问题，也尊重他人的时间。遇到问题后，先真正尝试解决：读报错、查资料、看相关代码，做必要的调试。如果仍然解决不了，再把问题和尝试过程带到群里讨论，~~而不是把大家当豆包~~。

所以，这篇文章希望大家都认真看一下：[提问的智慧](https://lug.ustc.edu.cn/wiki/doc/smart-questions/)。

提问时，尽量说明你想做什么、实际发生了什么、使用了什么环境，以及已经尝试过哪些方法。相关代码和报错也请一并提供。这样既方便别人理解，也能帮助你自己梳理问题。

当然，群里不需要搞得过于严肃。基础问题可以问，看过资料仍然不理解也可以问。核心还是前面那句话：尊重自己的问题，尊重他人的时间。

另外，大家需要主动探索内核开发，不能只等着群里发布方向和任务。任务可以帮助你起步，但不能代替自己的思考。**只有真正亲手探索 OS，才能真正学会 OS。**

## 基本环境：网络与 VPN

在我们后续的学习和开发中，访问外网资源是绕不开的。无论是使用 GitHub、使用 ChatGPT，还是学习国外课程，例如 MIT 6.1810，都需要相应的网络环境。因此，**务必提前配置好可用的外网访问环境**，不要等到下载代码、配置工具、查阅资料时才处理这些问题。

前几天，我已经在群里分享了 Windows 下的 Clash 代理客户端，以及可以购买机场服务的渠道。大家根据群内资料，自行完成配置，并确认相关网站能够打开、项目能够下载。

AI 工具方面，我个人更推荐 ChatGPT、Codex 或 DeepSeek，不推荐把豆包作为这个方向的主要辅助工具。具体偏好放在后面的工具部分说。

## 知识范围

开发 OS 并不限定必须使用 C 语言，C++ 和 Rust 也可以用于裸机和内核开发。大家可以根据自己的兴趣选择，但下面主要以 C 语言为例介绍。

我平时除了使用 C，也会使用 Rust。使用 C++ 开发内核时，通常还需要根据运行时条件选择适用的语言特性，不能直接照搬应用开发中的所有用法。

下面这些内容，是学习过程中需要逐步掌握的知识。哪些要先学、哪些可以结合项目深入，我也会尽量说明。

### 基础学科

- **数学与数制基础：** 需要熟悉二进制、十六进制及其转换，理解基本的位运算。这些会在后续开发中反复用到，需要练熟。
- **英语阅读与词汇：** OS 开发中的架构手册、设备与驱动文档，以及大量网上资料，都是英文的。可以借助翻译工具，但要逐步具备对照原文理解技术内容的能力。

### 编程方面

#### 汇编语言

在内核开发前期，汇编基本是绕不开的，启动流程、异常处理等部分都会用到。

我们主要使用 RISC-V，初期涉及的汇编内容相对集中。后续会结合方向和任务，学习需要用到的基础指令与特权指令。这部分不必过度担心，但也不能跳过：关键代码需要能读懂，知道每一步在改变什么状态。

#### 编程语言

这里重点说 C 语言。基本语法需要掌握，尤其要认真学习**指针**，包括普通指针、函数指针，以及回调函数的使用。

同时，还需要学习 C 的预处理机制，例如 `#define`、`#ifndef`、`#endif`，以及宏中的 `##` 等用法。可以参考：[C 预处理器教程](https://www.runoob.com/cprogramming/c-preprocessors.html)。

结构体、枚举、位域等内容也需要了解，尤其要注意数据布局和内存之间的关系。

C 语言的基础语法本身不算最难的一关，大家可以加快这部分的学习进度，但要通过实际写代码确认自己掌握了，不能只看教程。

我早期学习 C 语言时，主要看过《C Primer Plus》。这本书比较厚，如果暂时不适合完整阅读，也可以选择其他网页教程或 B 站课程，边学边练。

#### 算法和数据结构基础

算法和数据结构的学习能够提升编程能力。虽然内核开发的初始阶段未必会用到很多复杂算法，但基础的数据组织方式和编程思维仍然很重要。

大家可以尝试每天做一道算法题，保持练习。下面是一些可以参考的资源：

- [Hello 算法](https://www.hello-algo.com/chapter_hello_algo/)
- [算法通关手册](https://algo.itcharge.cn/)
- [洛谷](https://www.luogu.com.cn/)
- [力扣](https://leetcode.cn/)

另外，我也推荐《算法竞赛》，作者是罗勇军、郭卫斌。感兴趣的同学可以看一下。

#### 编程工具及平台

熟练使用 Git 和 GitHub 很有必要。大家可以自行寻找教程，学习代码获取、版本管理、提交记录、分支和协作等基本操作。

AI 工具方面，我个人更推荐 ChatGPT、Codex 或 DeepSeek，而不是豆包。这是我在这个学习方向上的工具偏好。无论使用哪一种，都不能把回答直接当作结论，生成的代码也需要自己读懂、验证。

之前分享的 ChatGPT Plus 购买渠道也保留在这里，供有需要的同学自行了解；具体价格和服务内容以页面实际信息为准。注册和使用方法，大家自行探索。

[Plus 渠道](https://bbai.store/#offers)

#### Unix 使用经验

我们会经常接触 Unix 和类 Unix 系统的概念与使用方式，例如 Linux、macOS 中的相关环境。后续要开发的系统也会参考类 Unix 的设计，因此，需要积累这方面的使用经验。

如果目前主要使用 Windows，可以通过虚拟机安装 Linux，也可以使用 WSL2。先熟悉终端、文件与目录操作、权限，以及常用开发命令，再在实践中逐步深入。

#### 工具链

进行操作系统开发，必须逐步理解所使用的编译器、汇编器、链接器和 Make 等工具的行为。出现问题时，你需要知道报错大致意味着什么、问题发生在哪个环节，而不能只会复制构建命令。

编译和链接涉及的内容很多，可以在后续结合项目慢慢看，不要求一开始就全部掌握。

我们要进行的内核开发涉及裸机环境。面向 RISC-V 这样的目标平台时，通常需要使用相应的交叉编译工具链，而不是直接使用主机默认的编译配置。后续还会接触 `objdump`、`readelf`、`nm` 等工具，使用过程中要逐渐熟悉它们的作用。

#### 可执行文件格式

Windows 下常见的可执行文件采用 PE 格式，Linux 中常见的则是 ELF 格式。我们后续的项目也会使用 ELF，因此需要了解其中的相关结构，以及怎样解析和加载 ELF 文件。

这部分可以结合编译、链接和程序加载来学习，逐步理解文件中的信息如何对应到内存中的程序。

#### 平台内容

内核开发需要面向具体平台展开，因此，我们必须学习目标平台的架构与特权架构手册。

这些手册会说明相关机制、寄存器、指令及其约束，是理解初始化、异常处理、内存管理等流程的重要依据。涉及具体设备时，还需要查阅对应的设备文档。

**查手册是内核开发的基本功。** 如果一个问题在手册中有明确说明，而你完全没有尝试查阅，那么得到的回应可能就只是：“先去读手册吧。”如果已经读过但没有理解，欢迎带着具体段落和自己的疑问来讨论。

#### 概念与参考书籍

操作系统中会遇到很多概念，例如：

- COW：写时复制（Copy-on-Write）。
- VMA：虚拟内存区域（Virtual Memory Area）。
- VA：虚拟地址（Virtual Address）。
- PA：物理地址（Physical Address）。

除此之外，还有很多机制和实现方式的名称，需要在学习中逐步理解。遇到这些内容时，不能只记住缩写，还要弄清楚它们解决什么问题、为什么这样实现。

这里推荐几本参考书：

- 《操作系统导论》。
- 《现代操作系统》。
- 《深入理解计算机系统》（CSAPP）：内容较多，可以结合项目按需查阅，逐步理解程序与底层系统之间的联系。
- 《计算机组成与设计：硬件/软件接口》（RISC-V 版）：学习计算机组成和 RISC-V 相关内容时，可以作为参考书，结合实验深入阅读。

书和手册都需要结合实际代码来看。读到的概念能否在实现中对应起来，才是检验理解的重要一步。

## 学习路径

前面列出了需要接触的知识，下面说一下我们接下来准备怎么走。整体顺序是：**C 语言基础 → 操作系统基础 → 结合 RISC-V 学习并完成 xv6 实验 → 学习 Rust → 参加 rCore 的学习与实践 → 准备计算机能力大赛 → 深入学习 Linux 内核。**

### 第一阶段：C 语言基础

最开始先把 C 语言基础打好，尤其是指针、结构体、函数指针、位运算和内存相关内容。要求不只是看过语法，而是能够自己写程序、读懂代码，并对出现的问题做基本的分析和调试。

后面阅读 xv6 时，会反复用到这些知识。如果这一步只是照着教程抄过代码，进入内核之后就会很吃力，所以请认真对待。

### 第二阶段：操作系统基础

接下来学习操作系统基础，先对进程、调度、内存管理、虚拟内存、文件系统、中断与异常等内容建立基本认识。至少要知道这些机制在解决什么问题，后面读代码时才有可以对应的概念。

这部分如果暂时没有学，也不是后面就完全走不下去，但欠下的知识不会自动消失，之后只能边做边慢慢补。到时候既要理解代码，又要补概念，进度和理解都会受到影响。**能提前打好的基础，尽量提前打好。**

### 第三阶段：结合 RISC-V 学习 xv6

有了前面的基础之后，我会带大家一起看 RISC-V 的相关内容，结合 xv6 阅读代码、分析机制，并动手完成实验。

我们会把架构中的寄存器、特权级、异常处理和地址转换，与 xv6 中的具体实现对应起来，逐步理解启动、页表、进程、系统调用和文件系统等内容。这个阶段需要大家亲自读代码、查手册、做实验，不能只听讲解。

希望做到的，是完成实验之后，你能够解释自己的修改为什么有效，涉及哪些机制，以及出了问题应该从哪里查起。

### 第四阶段：学习 Rust，准备参加 rCore

完成前面的学习之后，再开始学习 Rust，为后续参加 rCore 的学习与实践做准备。

这一阶段需要认真理解 Rust 的所有权、借用、生命周期等内容，以及它们对代码组织方式的影响。之后在 rCore 的实践中，继续学习如何使用 Rust 实现操作系统，把之前在 xv6 中接触过的机制重新理解和实现一遍。

换一种语言实现，也需要重新思考数据怎样组织、资源怎样管理、接口怎样设计。希望大家能把之前学到的操作系统知识带过来，而不是换了语言就从头照抄代码。

### 第五阶段：准备计算机能力大赛

走完前面的阶段，基础和实践积累得差不多之后，我们再准备计算机能力大赛。具体参赛安排、题目和分工，会结合当时的赛事要求与大家的实际进度确定。

这个阶段要把已有知识用到更完整的任务中，练习功能实现、问题定位、测试和协作，也检验一下自己掌握的内容能不能真正用起来。

### 第六阶段：深入学习 Linux 内核

最后，再带着前面的积累深入学习 Linux 内核。从自己已经熟悉、也感兴趣的部分切入，逐步阅读相关代码，理解成熟内核怎样处理更复杂的实际问题。

这会是一段更长期的学习。希望到这个时候，大家已经具备自己查资料、读代码、做实验和追踪问题的能力，能够选择一个方向持续深入。

这就是目前准备推进的路线。每个阶段都需要实际投入，具体节奏会根据大家的进展调整，但需要掌握的东西不会因为赶进度就省掉。**我会带大家一起看、一起做，最终能理解多少、走到哪里，仍然取决于你自己的投入。**

## 不惧挑战？

### 欢迎来到内核开发的世界

这是一个充满挑战的领域，并不是每个人都能坚持到自己设想的终点。甚至只是让自己写的内核输出一句 `Hello, world!`，都可能卡在编译、链接、启动或者输出设备的某个环节。

但也正因为如此，当那句 `Hello, world!` 终于出现在终端上时，它的意义会很不一样。为了这行输出，你可能已经追过启动代码、改过链接脚本、检查过地址，还查过串口的寄存器。你知道它经过了哪些环节，也知道自己终于把哪几部分接通了。那一刻，前面卡住你的东西，开始变成你能理解、能控制的东西。

接下来，这种时刻还会出现很多次。

你会亲手建立页表，看到一个虚拟地址通过自己配置的映射访问到物理内存；也会因为一个权限位写错，迎面撞上异常，再顺着异常原因和出错地址把问题找出来。原来书上的“虚拟内存”，可以这样具体地呈现在你面前。

你会保存寄存器、切换栈，让处理器从一个任务切换到另一个任务。等到时钟中断和调度器配合起来，几个任务开始轮流运行时，你会发现，平时习以为常的“同时运行多个程序”，背后竟然可以由自己写下的这些代码一步步实现。

你会设计系统调用，让用户程序请求内核提供服务。从用户态进入内核，再带着结果返回，这条路径上的每一步都可以跟踪、检查和修改。以后再看到程序申请内存、读写文件，你脑海里就会多出一条能解释它如何发生的路径。

再往后，你可能会写驱动、做文件系统，让系统读出磁盘上的内容，加载一个程序，再运行自己写的 Shell。当终端开始响应你的命令时，你会清楚地知道：支撑这些操作的内存管理、调度、输入输出和程序加载，有多少是自己一点点搭起来的。

**内核开发很有意思的一点，就是你的好奇心可以一直追下去。** 一个函数为什么能执行？程序为什么能访问这段内存？这次异常是谁触发的？设备怎么通知 CPU？从代码追到汇编，从汇编追到寄存器和硬件机制，很多原本被藏起来的细节，都会逐渐变得清楚。

当然，这个过程也会有长时间没有输出、反复重启、改了一处又坏了另一处的时候。有时折腾很久，最后发现只是一个地址、一处对齐或者一个标志位出了问题。但当你终于解释清楚那个看似莫名其妙的现象，并亲手把它修好时，那种成就感也很直接：你确实比昨天更理解这台机器了。

等这些部分逐渐连接起来，你得到的会是一个能够运行的系统，也会是一套越来越完整的理解。课本上的概念、手册里的描述和屏幕上的代码，开始能够相互对应。你还可以继续修改自己的设计，观察行为怎样变化，比较不同实现的代价，让系统按照你的想法演进。

也许你会继续走下去，做出自己的操作系统，甚至朝着创造下一个 Linux 的目标努力；也可能深入 Linux 的某个方向，把其中一项机制研究透，并做出有价值的优化。目标可以很远，而眼前每一个被你真正弄懂、亲手实现的机制，都算数。

对我来说，内核开发是编程领域里最值得追求的方向之一。亲手让系统运转起来，看到自己写的代码开始管理内存、调度任务、响应设备，这种感受让我愿意一直投入下去。这也是我建这个群、想找大家一起探索的原因。

**难就是难，投入也不会少。前面的困难我已经讲清楚了，而这些困难背后能看到的东西，也值得我们亲自走进去看看。**

如果读到这里，你仍然想知道“它到底是怎么工作的”，仍然想亲手把它做出来，那就开始吧。

**欢迎来到内核开发的世界。**
